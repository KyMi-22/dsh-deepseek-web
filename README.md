## 能做什么

装上之后，侧边栏多出一个 **「对话」** 分组，里面是你在 [chat.deepseek.com](https://chat.deepseek.com) 上的对话。点开就能看完整历史，也能直接在这里继续聊。

继续对话时选 **DeepSeek 网页版** 模型，请求走的是网页端，费用记在网页产品上，**不花 API 额度**。

两边是通的：

- 在 DSH 里聊的内容，网页端也会有
- 在网页端继续聊过的对话，回 DSH 再接着聊时能接上

还有 **快捷侧问**：正在用内置模型对话时，点会话头部（右上角三点按钮旁）的 ⚡ 按钮，右侧面板里可以用网页版模型问旁边的小问题。面板打开时自动把当前对话压缩成背景带过去；问答只留在面板里，**原对话的上下文一点不变**。详见「快捷侧问」一节。

## 安装

装完都要**重启 DSH**。重启后「设置 → 插件」里应该能看到 `dsh-deepseek-web` 和它的图标。

### 方式一：在 DSH 界面里装（推荐）

1. 打开 DSH，侧边栏底部点 **设置**
2. 左侧选 **插件**
3. 点 **添加插件**
4. 在「包名或地址」里填：

   ```
   https://github.com/KyMi-22/dsh-deepseek-web
   ```

5. 点 **安装**，等它跑完
6. 回到插件列表确认 `dsh-deepseek-web` 是启用状态，然后重启 DSH

> 这一步会通过 git 访问 github.com。如果连不上或者一直超时，用下面的 tgz 方式。

### 方式二：从下载的 tgz 装（GitHub 连不上时用）

只要浏览器能打开下载页面就行，不经过 git。

1. 打开 [Releases](https://github.com/KyMi-22/dsh-deepseek-web/releases)，下载最新的 `dsh-deepseek-web-x.y.z.tgz`
2. 设置 → 插件 → **添加插件**
3. 在「包名或地址」里填 tgz 的**完整路径**，例如：

   ```
   C:\Users\你\Downloads\dsh-deepseek-web-0.1.13.tgz
   ```

4. 点 **安装**，之后同样重启 DSH

> 路径里的反斜杠直接填，不用转义。不知道完整路径的话，在文件管理器里右键 tgz →「复制文件地址」。

### 方式三：命令行

需要先有 Node（`^22.19.0` 或 `>=24`）。按你用的 DSH 形态选一条：

**桌面版**

```bash
npx @deepseek-ai/dsh plugin --profile desktop add github:KyMi-22/dsh-deepseek-web
```

**Web 版**

```bash
npx @deepseek-ai/dsh plugin --profile web add github:KyMi-22/dsh-deepseek-web
```

> 如果 `dsh` 已经在你的 PATH 里（比如从源码构建过），把开头的 `npx @deepseek-ai/dsh` 换成 `dsh`。
>
> 装本地 tgz 同理，把 `github:...` 换成 tgz 的路径即可。

## 开始使用

### 1. 拿到 user token

1. 浏览器登录 [chat.deepseek.com](https://chat.deepseek.com)
2. 按 `F12`，切到 **Console** 标签
3. 粘贴这一行并回车，复制输出的内容

```js
JSON.parse(localStorage.userToken).value
```

输出的是一长串字符。这就是你的登录凭证，**不要发给别人**。

### 2. 填进插件

DSH 里打开 **设置 → DeepSeek 网页版**，把 token 粘进输入框，点「保存并验证」。验证通过会显示你的账号。

### 3. 同步对话

同一页点「立即同步」。之后默认每 5 分钟自动同步一次，不用管它。

### 4. 开始聊

回到侧边栏，展开 **对话** 分组，点任意一条就能看历史。想继续聊，在输入框的模型选择器里选 **DeepSeek 网页版**。

## 两个方向的同步规则

插件只在一种情况下会写网页端：**用「DeepSeek 网页版」模型聊天时**。其他情况网页端不会变。这两件事容易搞混，分开说。

### 情况一：导入的对话，改用 DSH 的模型继续

原本在网页端的对话导入之后，你切到 DSH 自带的模型（比如 `DeepSeek V4`）接着聊。

| | 影响 |
|---|---|
| **网页端** | 对话**定格在导入那一刻**。之后在这里聊的内容，网页端看不到 |
| **DSH** | 正常继续。导入的历史是普通消息，模型能完整读到 |
| **文件** | **能生成**。相对路径落在会话工作目录 `$DSH_HOME/deepseek-web/conversations`，绝对路径按模型指定的位置 |

网页端不同步不是插件偷懒：官方模型的请求发往 `api.deepseek.com`，网页对话住在 `chat.deepseek.com`，是两套独立的产品，API 没有「往某个网页对话追加一条消息」这种接口。

> 想让网页端也保持同步，就别切模型——继续用「DeepSeek 网页版」。

### 情况二：在 DSH 里新建对话，用 DS 网页模型

在 DSH 里新建会话（哪个分组都行），模型选择器里选「DeepSeek 网页版」。

| | 影响 |
|---|---|
| **网页端** | 会**创建对应对话**，你的提问和模型的回复都写进去 |
| **DSH** | 正常，有完整的本地记录 |
| **文件** | **不会生成**。网页接口没有工具调用通道，模型只能输出文本 |
| **分组** | 与会话在哪个分组**无关**。即使建在「对话」分组之外，同样会写到网页端 |

这就是这个插件的主要用法：用网页版的免费额度跑 DSH 的对话。

### 情况三：在原 DSH 对话里中途切换到网页模型

本来用 DSH 内置模型聊了很久的会话，中途在模型选择器里换成「DeepSeek 网页版」。

| | 影响 |
|---|---|
| **网页端** | 会**新建一个网页对话**，而且它**看不到这个 DSH 会话之前的聊天**——适配器只发最新那一句 |
| **DSH** | 这一轮的提问和回复继续追加进原会话，**上下文变长** |
| **之后** | 再切回 DSH 内置模型时，要读的上下文里就多了这些轮，token 消耗随之上升 |

这是三种情况里最别扭的一种：网页端拿到一个「只有一句」的孤立对话，而 DSH 里多了一段网页端并不知情的往返。两边都只看到一半。

**建议**：想用网页模型就新建一个会话，不要在已有长对话的中间换模型。

### 一句话对照

| 场景 | 网页端 | DSH 侧上下文 | 能生成文件 |
|---|---|---|---|
| 直接在网页端聊 | 正常，多一条消息 | 无关 | 否 |
| 导入的对话 + DSH 模型 | 定格在导入时，看不到后续 | 正常增长 | 是 |
| 任意会话 + 网页版模型 | 创建或写入对应对话 | 正常增长 | 否 |
| 长对话中途切到网页模型 | **新建一个只有一句的孤立对话** | **额外变长** | 否 |

## 按钮与操作说明

设置页「DeepSeek 网页版」里的几个按钮：

| 按钮 | 作用 |
|---|---|
| **保存并验证** | 先校验 token 是否有效，通过才写入磁盘。无效的 token 不会被保存 |
| **检测当前凭证** | 用已保存的 token 查一次账号信息，确认它还没过期 |
| **立即同步** | 手动拉取一次网页端对话，不用等后台定时 |
| **撤销导入** | 归档分组下的会话、删掉导入的那些文件、删除工作区和导入记录（见下） |
| **热重载并刷新** | 重新组合插件树并刷新页面，让新导入的会话立刻出现 |

常见操作：

| 想做什么 | 怎么做 |
|---|---|
| 马上拉取新对话 | 点「立即同步」 |
| 同步了但侧边栏没变化 | 点「热重载并刷新」 |
| 清空导入的对话 | 点「撤销导入」 |
| 调整同步范围 | 插件配置里的 `syncWindow`（默认只同步最近 7 天） |

**关于撤销**：会把「对话」分组下的会话**归档**，删掉插件导入的那些文件，然后删除分组。你在 DSH 里自己新建、用网页版模型聊过的对话**只归档、文件保留**，不会丢。

## 可选设置

在插件配置里可以调：

| 字段 | 默认 | 说明 |
|---|---|---|
| `syncWindow` | `7` | 同步最近多少个自然日（**含今天**）。默认 `7`，即今天加前六天；也可写 `month`（本月）或 `all`（全部） |
| `syncIntervalSeconds` | `300` | 自动同步的均值间隔，实际会上下浮动 30% 左右；`0` 表示只手动同步 |
| `autoSync` | `true` | 关掉后台自动同步 |
| `baseUrl` | `https://chat.deepseek.com` | 站点地址 |

**窗口是滚动的。** 每次同步都用**当时的时间**重算起点，所以每过一天窗口自动前移一天：10-23 的「最近 7 天」是 10-17 起，10-24 就变成 10-18 起。

这跟网页产品自己「最近 7 天」的划分一致。已经导入的对话**不会**因为窗口前移而被删除——窗口只决定下一轮同步去拉哪些，不负责清理。

## 安全

**token 存在哪**：`$DSH_HOME/deepseek-web/state.json`。目录权限 `0700`、文件 `0600`（POSIX），设置页只显示末四位，不回显完整值。

不想让它落盘，用环境变量启动 DSH：

```powershell
$env:DEEPSEEK_WEB_TOKEN = '<token>'
```

环境变量优先级最高，这时 `state.json` 里的旧值会被忽略。

**实际风险**，按可能性排序：

1. **云同步**——`~/.dsh` 如果落在 OneDrive / Dropbox / iCloud 的同步目录里，token 会跟着上云。**这是唯一值得主动检查的一条。**
2. 同机其他用户——靠文件权限隔离。
3. 本机恶意软件——任何本地凭证都挡不住，DPAPI 也一样。

保护级别与浏览器保存的登录 cookie 相当。

**数据发到哪**：只发往 `chat.deepseek.com`，也就是你本来就在用的那个网站。不向任何第三方发送。

**网页版会话不会写你的本地文件**：网页接口没有工具调用通道，适配器只输出文本；另有一道白名单拦截兜底，只放行只读工具。

**为什么不用 DSH 的登录态**：DSH 登录的是 API 平台（`platform.deepseek.com`），和网页版（`chat.deepseek.com`）是两套独立的凭证体系——同一个账号不代表同一个 token。想拿网页版 token 只能从浏览器存储里取。详见 [DESIGN.md](docs/DESIGN.md#token)。

## 目录结构

**插件本身**：

```
index.js           Host 入口：provider 注册、同步引擎、设置页路由、快捷侧问路由、工具拦截
client.js          设置页 + 快捷侧问面板
src/api.js         网页端接口客户端：分页、历史、上传、SSE、错误分类
src/adapter.js     provider 适配：messages → prompt，图片引用收集，SSE → StreamChunk
src/sync.js        网页对话 → 种子会话；工作区；撤销
src/store.js       插件状态（token、会话绑定、导入账本、侧问线程）
src/pow.js         DeepSeekHashV1 求解器
src/pow-async.js   求解放到 worker 线程，带进程内回退
src/pow-worker.js  worker 入口
src/http.js        设置页路由的 JSON / 请求体工具
src/tool-guard.js  网页版会话的工具白名单
src/quick-ask.js   快捷侧问：压缩背景、每会话一条网页线程、SSE 泵
src/quick-ask-tag.js 侧问线程的命名与导入排除规则（`SideBar：<对话名>`）
```

**安装后在本地产出的文件**：

```
$DSH_HOME/
├─ deepseek-web/
│  ├─ state.json          token、会话绑定、导入账本
│  └─ conversations/      导入会话的 cwd（空目录，是「对话」工作区的锚点）
└─ sessions/
   └─ --<cwd-slug>--/     按会话的工作目录分桶
      └─ <session-id>/
         └─ session.v4.jsonl.zstd   会话日志（消息、标题、usage）
```

两个容易疑惑的点：

- **`conversations/` 本身是空的**。DSH 按会话的 `cwd` 把会话分桶存储，真正的对话数据在 `sessions/` 下对应 slug 的目录里。`conversations` 只是那个 `cwd` 的物理锚点——工作区必须指向一个真实存在的目录。
- **导入的对话拿到新 UUID**，不是网页端的 id，所以两边身份独立。

详见 [DESIGN.md](docs/DESIGN.md#模块)。

## 实现原理

两个方向是分开的：

**导入**：拉网页对话的历史 → 转成 DSH 的标准种子事件（`turn/start`、`step/start`、`user/message`、`request/header`、`session/title`、`assistant/message`…）→ 用 `agentLoop.createAgent` 落成一条**普通会话**，`cwd` 指向 `conversations`。

**续聊**：选「DeepSeek 网页版」模型 → 适配器只把**最新一句用户消息**发给绑定的网页对话（靠 `parent_message_id` 接上历史），把 SSE 增量翻译成 `StreamChunk` 回传。

几个值得知道的点：

- 每轮**只发一句话**：不带 system prompt、不带历史轮次、不带 DSH 注入的记账消息（靠 `source.kind` 过滤）
- 发消息要过 **PoW 挑战**，求解器是网页端 `DeepSeekHashV1` 的移植（跑在 worker 线程，避免卡住 Host）
- **标题生成、历史压缩**这两类辅助调用在本地作答，不碰网页端
- 发消息前会检查父消息是否过期（超过 60 秒就重读网页历史），避免从旧分支续接

完整的协议细节、种子事件格式、撤销为什么必须先归档、凭据提交边界、重试标记、SSE 解析，都在 **[docs/DESIGN.md](docs/DESIGN.md)**。

## 常见问题

**Q：输入框里的模型选择器找不到「DeepSeek 网页版」？**

先确认插件已启用（设置 → 插件），然后重启 DSH。provider 是在插件加载时注册的。

**Q：同步完成但侧边栏是空的？**

点设置页的「热重载并刷新」。侧边栏读的是会话索引，有时候需要重新构建一次才看得到。

**Q：提示 token 无效？**

token 会过期。重新执行上面「拿 token」的三步，用新的替换掉。

**Q：会话里的模型为什么不会调用工具？**

DeepSeek 网页版的接口只收一段文本，没有函数调用通道。这是接口本身的限制。需要工具时，在 DSH 里新建一个会话，选官方 API 的模型即可。

## 限制

- **不发起工具调用**：网页端接口没有 function-calling 通道。联网搜索和深度思考是网页版自带的能力，通过模型选择器里的对应版本启用。
- **不支持内嵌网页**：`chat.deepseek.com` 设置了 `frame-ancestors 'none'`，任何页面都无法用 iframe 嵌入。
- **同步有延迟**：网页端没有推送接口，只能轮询。
- **网页对话会一直变长**：一个 DSH 会话绑定一个网页对话后就不再更换，聊得越久上下文占用越多。中途想问小问题用「快捷侧问」，别在长对话里切模型。

### 图片与文件输入

可以直接在对话里贴图，也可以用输入框的「文件」菜单附加文档（PDF、Word、Excel、PPT、TXT 等）。插件把文件上传到网页端（走和浏览器一样的 `upload_file` 接口，每次上传需要单独过一次 PoW），拿到文件 id 后随消息一起发出——所以文件保存在网页对话里，不在本地落盘。

几点行为差异值得知道：

- **上传要等解析**：文件传上去后网页端异步解析（图片一般一两秒，大文档更久），解析完成前发送会失败。插件会自动等，超时是 60 秒。
- **解析失败会自动再试一次**：网页端的解析队列偶尔会返回 `FAILED`，插件会重新上传并再等一次；两次都失败才报错，报错里带文件名、类型、大小和服务器状态，便于定位。
- **类型由网页端决定**：网页端按文件名扩展名判断类型，不接受的扩展名会被拒绝并给出错误。单文件上限 20 MB。
- **只附文件不加文字也能发**：prompt 会自动带上文件名，保证网页端收到非空文本。
- **附件服务不可用时**：对话分组的文件读自 DSH 的附件存储。个别部署没挂载它时，带附件的消息会明确报错，纯文本不受影响。

## 快捷侧问

用内置模型聊到一半，遇到一个小问题想问又不想消耗 API token——点会话头部的 **✨ 按钮**（右上角三点按钮旁边），右侧打开一个独立面板，用网页版模型提问。

它解决的是「中途切模型」的两个代价：

| | 中途切到网页模型 | 快捷侧问 |
|---|---|---|
| 网页端 | 新建一个只有一句的孤立对话 | 一个带背景摘要的侧问线程 |
| 原对话上下文 | 被这轮往返撑长，之后每轮多耗 token | **零增长** |

行为细节：

- **打开即带背景**：首次提问时，当前对话被压缩成摘要（保留人类输入和助手回答，从最新往回装进约 12000 字符）作为网页线程的第一条消息。空白对话也能用，只是没有背景。
- **一个会话一条线程**：线程按 DSH 会话复用，重开面板能接着上次的问答聊。「刷新背景」按钮丢弃当前线程、用**最新**的对话内容重建——原对话聊出新进展后点它。
- **网页端的命名与导入**：侧问线程在网页端统一命名为 `SideBar：<对应 DSH 对话名>`。同步导入有明确规则：**带 `SideBar：` 前缀的对话永远不导入**，所以网页端不会因此多出一堆侧栏对话。刷新背景留下的旧线程同样带这个前缀，可随时在网页端手动删除。
- **回复按 Markdown 渲染**：标题、粗体/斜体、行内代码、代码块、列表、引用、链接、表格都会正常显示；用户提问保持原文不动。流式输出到一半时也能读——未闭合的代码块按代码渲染。
- **每条消息可复制、带时间**：消息框下面一行元信息——复制按钮（点击复制原文，短暂显示勾选）和发送/作答时间（`HH:mm`）；旧线程没有时间记录就不显示。
- **输入框**：套用 DSH 原生 composer 的两段式布局（多行输入 + 底部工具栏），背景做成了半透明毛玻璃（背景模糊 + 主题描边），明暗主题都跟宿主一致。左下角是**网页端模型选择**（普通对话 / 深度思考 / 智能搜索 / 搜索 + 深度思考），选择结果决定这一问走哪条网页路由；右下角是圆形发送按钮。Enter 发送、Shift+Enter 换行。
- **附件**：输入框左下角的回形针可以一次选多个文件，选中的文件先上传到网页端，发送时随问题一起带上（文件名会显示在对应的提问气泡里）；只附文件不打字也能发。
- **紧凑居中**：对话列（说明卡、消息、输入框）收在面板宽度 80% 的居中列里，两侧各留 10% 留白，聚焦感更强。
- **说明卡可折叠**：面板顶部的说明装在一个消息框里，点标题行收起/展开，偏好会记住。
- **生命周期**：问答记录存在 `state.json`（`quickAsk` 账本），每个线程最多保留 50 组问答。撤销导入不会清理侧问线程——它们与导入的会话无关。

## 后续计划

**实现内置更新**

现在升级只有两条路：重新跑一次安装命令，或者去 Releases 页面下载 tgz 再装。计划在设置页加「检查更新」——拉 GitHub Release 的最新 tag 和当前版本比对，有新版就下载 tgz 并本地安装，装完提示重启。

需要考虑：走哪个源（GitHub 直连可能不通，要能退回 tgz 下载）、失败时怎么回滚（装坏了不能把在用的版本弄没）、以及要不要自动检查还是只手动点。

**「导入即快照」改为增量追加**

导入的会话在同步后是静态快照；网页端后续新增的消息做不到真正的增量追加（导入的会话已 dispose）。目前靠「继续对话时刷新父消息 id」弥补，真正的追加需要 Host 支持。
